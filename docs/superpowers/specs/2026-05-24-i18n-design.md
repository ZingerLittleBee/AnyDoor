# i18n (zh-Hans + en) Design

**Date:** 2026-05-24
**Scope:** Add runtime-switchable internationalization to AnyDoor, supporting Simplified Chinese (zh-Hans) and English (en).

## Goals

- Support `zh-Hans` and `en` across the entire user-facing surface.
- Default to the system preferred language; allow per-app override (System / 中文 / English) via Settings.
- Switching language inside the app takes effect immediately — no relaunch.
- Build on Apple's String Catalog (`.xcstrings`) so future locale additions are config-only.

## Non-Goals (Out of Scope)

- Documentation: `README.md`, `CHANGELOG.md`, `docs/landing-page/*`.
- Brand name "AnyDoor" — kept as-is in both locales.
- Plural / gender variant rules (current copy needs none; catalog natively supports adding them later without architectural change).
- A third locale (architecture is multi-locale-ready: extend `LanguagePreference` + add `.lproj` only).
- SF Symbols system-default accessibility labels (kept as OS default).
- Sparkle updater UI — Sparkle ships its own localized `.strings` and reads from its own bundle; we do not touch it.

## Architecture

### Resource layer

- Single source of truth: `Sources/AnyDoor/Resources/Localizable.xcstrings`.
- `Package.swift` adds `defaultLocalization: "en"` and the executable target declares `resources: [.process("Resources")]`.
- Build output bundles `.lproj/` folders into the SPM-generated module resource bundle (`AnyDoor_AnyDoor.bundle`), accessed at runtime via `Bundle.module`.

### Runtime layer — `LocalizationManager`

New `Sources/AnyDoor/Services/LocalizationManager.swift`:

- `@Observable @MainActor` singleton (`LocalizationManager.shared`).
- `enum LanguagePreference: String, CaseIterable { case system, zh, en }`, persisted via `@AppStorage("dev.bybee.AnyDoor.language")`.
- `var effectiveLocale: Locale` — when preference is `.system`, resolves against `Locale.preferredLanguages` in the supported set (`zh-Hans`, `en`); falls back to `en` if no match.
- `var bundle: Bundle` — resolves `Bundle.module` to its language-specific `.lproj` sub-bundle. This is the key to instant switch: SwiftUI's default `Text("key")` reads from `Bundle.main` under the process locale and won't re-resolve when `\.locale` changes — so all string lookups must go through the manager's bundle.
- Setting the preference updates `@AppStorage`, recomputes `effectiveLocale` / `bundle`, and notifies SwiftUI via `@Observable`.

### String access — `L10n`

New `Sources/AnyDoor/Utilities/L10n.swift`:

- `enum L10n.Key: String, CaseIterable` — type-safe namespace for every translatable string. Raw values are the dot-notation keys stored in the catalog.
- Free function `L(_ key: L10n.Key, _ args: CVarArg...) -> String`:
  - Calls `String(localized: LocalizedStringResource(key.rawValue), bundle: manager.bundle, locale: manager.effectiveLocale)`.
  - With format args, passes through `String(format:locale:)` using `effectiveLocale` so numeric / percent formatting tracks the language.
- View wrapper `LocalizedText(_ key: L10n.Key)`:
  - Reads `LocalizationManager` from `@Environment`, so it re-renders on preference change.
  - Internally renders `Text(L(key))`.

### Injection point

`AnyDoor.swift` adds at both the `MenuBarExtra { ... }` and `Settings { ... }` root content:

```swift
.environment(localizationManager)
.environment(\.locale, localizationManager.effectiveLocale)
```

`AppDelegate` constructs / owns the manager alongside `ModelContainer`.

## Key Naming Convention

Hierarchical dot notation; one `L10n.Key` case per string:

- `panel.*` — menu bar panel rows, empty state, hover popover
- `settings.general.*`, `settings.panel.*` — Settings tabs
- `builtin.muteAudio`, `builtin.lockScreen`, `builtin.appShortcuts`, ... — one per `BuiltinItem.Kind`
- `toast.*`, `alert.*` — runtime feedback (permission denial, success, failure)
- `menubarIcon.sparkles`, `menubarIcon.bolt`, ... — `MenuBarIcon.Choice` decorative names
- `hotkey.recorder.*` — hotkey recording UI strings
- `common.save`, `common.cancel`, `common.delete`, ... — shared verbs

## Call-Site Migration Rules

| Old | New |
|---|---|
| `Text("应用快捷键")` | `LocalizedText(.builtinAppShortcuts)` |
| `return "静音"` inside a model | `return L(.builtinMuteAudio)` |
| `Button("保存") { ... }` | `Button { ... } label: { LocalizedText(.commonSave) }` |
| NSAlert / Toast message | `L(.toastPermissionDenied)` |
| `Choice(name: "sparkles", title: "闪光")` | `Choice(name: "sparkles", titleKey: .menubarIconSparkles)` — struct field changes from `String` to `L10n.Key`, rendered as `L(c.titleKey)` |

### Model-layer rule

Models never store resolved localized strings — they expose `L10n.Key` (or a function returning one). Resolution happens at the view layer. This keeps model unit tests deterministic and avoids capturing manager state in value types.

- `BuiltinItem.displayName: String` → either becomes `displayKey: L10n.Key` (renamed) or a computed `displayName` that calls `L(displayKey)`. Decision: rename to `displayKey` and render via `L(...)` at the call site for clarity.
- `MenuBarIcon.Choice.title: String` → `titleKey: L10n.Key`.

## Data Flow on Language Switch

1. User opens Settings → General → picks 中文 / English / 系统.
2. `LocalizationManager.preference` setter writes `@AppStorage`, recomputes `effectiveLocale` and `bundle`.
3. `@Observable` notifies SwiftUI; views containing `LocalizedText` / `L(...)` re-render.
4. All visible strings update immediately. Persisted choice survives relaunch.

## Edge Cases

- **Unsupported system language** (e.g. Japanese macOS) → `.system` resolves to `en`.
- **Missing key in catalog** → `String(localized:)` returns the key string; DEBUG builds raise `assertionFailure("missing key: \(key.rawValue)")` so it surfaces during development. Release is silent.
- **Format argument mismatch** — developer-time only; catalog entries use positional specifiers (`%@`, `%lld`, `%.0f%%`).
- **`AppleLanguages` UserDefault is not modified** — we use our own bundle resolution, so Sparkle, system dialogs, and accessibility prompts keep their own logic.
- **AppKit surfaces** (`NSAlert`, `NSMenu`, `NSWorkspace.shared.open` confirmation): manually pass `L(...)` results.

## Testing

New `Tests/AnyDoorTests/Localization*.swift`:

- **`LocalizationCoverageTests`** — loads `Localizable.xcstrings` JSON from the test bundle, asserts every `L10n.Key.allCases` raw value has a non-empty translation in both `zh-Hans` and `en`. Prevents missing translations from shipping.
- **`LocalizationManagerTests`**
  - `.system` with controlled `preferredLanguages` resolves correctly (zh-Hans Mac → zh, en Mac → en, ja Mac → en).
  - `.zh` / `.en` overrides force the correct locale regardless of system.
  - Setting `preference` updates both `effectiveLocale` and `bundle`.
- **`BuiltinItemLocalizationTests`** — every `BuiltinItem.Kind` maps to a valid `L10n.Key` (no orphan kinds).

## Migration Plan

Each phase compiles independently.

1. **Scaffold** — `Package.swift` change, empty `Localizable.xcstrings` with one demo key, `LocalizationManager`, `L10n.Key` (initial cases only), `L(_:)`, `LocalizedText`. Wire environment injection. Verify end-to-end with one demo string.
2. **Models** — `BuiltinItem`, `MenuBarIcon`, any other display-bearing data types.
3. **Views — panel surface** — `MenuBarView`, `PanelRowView`, `HotkeyLabel`, `HotkeyRecorder`, `AppShortcutsPopoverView`, `HoverPopover`, `ClipboardHistory*`, `PortManagerPopoverView`, `PortListView`, `UpdateBannerView`, `ToastView`, `ScreenshotPreviewWindow`.
4. **Views — settings window** — `SettingsView`, `PanelSettingsView`, `GeneralSettingsView` (and add the language Picker here).
5. **Services** — Provider error / feedback strings, `AppleScriptRunner` / `ShellRunner` UI-surfaced errors, `UpdateService` / `AutomationPermission` user-facing messages.
6. **Coverage tests** — turn on `LocalizationCoverageTests` once the full key set is populated.

## Risks & Open Questions

- **`@Observable` re-render scope**: SwiftUI views that read `LocalizationManager` via `@Environment` re-render on change; views that only call the free `L(...)` without observing the manager will not. Mitigation: prefer `LocalizedText` for view-tree strings; use `L(...)` only for one-shot strings (toast bodies, NSAlert messages) which are recreated on each call.
- **Catalog editing without Xcode**: `.xcstrings` is JSON — editable by hand or via Xcode. We will keep entries grouped by namespace prefix and pre-populate via a one-time script if the count justifies it.
- **First-run default**: on a fresh install, `@AppStorage` is `nil` → manager treats this as `.system`. No migration needed.
