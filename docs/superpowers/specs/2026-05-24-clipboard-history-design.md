# Generated Clipboard History — Design

**Date**: 2026-05-24
**Status**: Approved (design phase)
**Author**: Brainstorming session

## Summary

Add a local history for content generated by AnyDoor itself: OCR text, picked
colors, decoded QR-code payloads, and interactive screenshots copied to the
clipboard. The history is intentionally **not** a full clipboard manager. It
does not monitor the system clipboard, does not capture content copied from
other apps, and does not run a background pasteboard watcher.

The existing actions keep their current click behavior. Hovering any of these
four action rows opens a side popover showing that action's recent history:

- `屏幕取词` — OCR text history
- `屏幕取色` — color HEX history
- `识别二维码` — QR payload history
- `截图到剪贴板` — screenshot image history

Items expire automatically after 7 days. Each kind also has a hard cap of 100
items to keep storage bounded. Text-like records live in SwiftData. Screenshot
metadata lives in SwiftData, while full PNG files live under AnyDoor's existing
Application Support directory.

## Goals

- Record only successful outputs produced by AnyDoor's OCR, color picker,
  QR-code recognition, and screenshot actions.
- Preserve the current action click semantics exactly: clicking a panel row
  still runs the action.
- Show history on hover for the four supported action rows.
- Let users navigate history with mouse hover or `↑` / `↓`.
- Let users preview the selected item with `Space`.
- Let users copy the selected item back to the clipboard with click or `Enter`,
  then close both the history popover and the main AnyDoor panel.
- Retain history for 7 days and prune older records automatically.
- Cap history at 100 items per kind, pruning oldest overflow records.
- Provide a clear-all-history action in Settings.
- Keep history failures non-disruptive: if the original action succeeded, a
  history write failure must not turn the action into a user-visible failure.

## Non-Goals

- No full clipboard monitoring.
- No global clipboard history.
- No search in the first version.
- No history sync.
- No user-configurable retention window in the first version.
- No per-item pinning or favorites.
- No default hotkeys for opening history popovers.
- No transformation of QR payloads or OCR text.
- No OCR over stored screenshot history.
- No compression settings or custom export flow for screenshots.

## Clarifications Captured

| Topic | Decision |
|-------|----------|
| Retention | 7 days, automatic pruning |
| Hard cap | 100 items per kind |
| Scope | Only AnyDoor-generated outputs |
| History entry points | Hover on the existing OCR, color, QR, and screenshot action rows |
| Row click behavior | Unchanged; runs the original action |
| Copy from history | Click or `Enter`; copies to pasteboard and closes history + main panel |
| Preview | `Space` previews the selected item; no copy, no close |
| Selection | Mouse hover and `↑` / `↓` both update selected item |
| Search | Not in first version |
| Screenshots | Store full PNG files for 7 days; show thumbnails in history |
| Clipboard manager behavior | Explicitly out of scope |

## UX

### Panel rows

The four target rows remain `.action` rows. They do not become `.submenu`
items, so their existing hotkey and click paths continue to work through
`PanelStore.run`.

On hover, `MenuBarView` mounts a history popover to the right of the hovered
row. This uses the same `HoverPopover` / `HoverGate` infrastructure currently
used by App Shortcuts and Port Manager, generalized so a row can have a hover
popover even when its `BuiltinItem.Kind` is `.action`.

### History popover

The popover is kind-specific. Hovering `屏幕取词` never shows color, QR, or
screenshot records.

The popover displays:

- A compact header with the kind title and visible item count.
- A list of recent 7-day records, newest first.
- An empty state when there are no records.
- A lightweight inline failure state when a screenshot file is missing.

No search field appears in this version.

### History item interaction

- Mouse hover selects a row.
- `↑` and `↓` move the selection.
- Click copies that item back to `NSPasteboard.general`, then closes the
  history popover and the main panel.
- `Enter` does the same as click for the selected item.
- `Space` opens a preview for the selected item.
- `Esc` closes an open preview. If no preview is open, `Esc` closes the
  history popover.

The popover must be key-capable (`HoverPopover.needsKeyFocus = true`) while
mounted, because the keyboard interaction is part of the primary workflow.

### Preview

Text preview:

- OCR: full recognized text, preserving newlines.
- QR code: full payload text. This is acceptable because the user explicitly
  opened the QR history. Toasts still never display QR payloads.
- Color: large swatch, HEX value, and timestamp.

Screenshot preview:

- A larger image preview loaded from the stored PNG.
- If the file is missing or cannot be decoded, show a failure state instead of
  crashing or copying stale metadata.

## Data Model

Add a new SwiftData model:

```swift
@Model
final class ClipboardHistoryItem {
    @Attribute(.unique) var id: UUID
    var kind: String
    var text: String?
    var fileName: String?
    var colorHex: String?
    var previewTitle: String
    var previewSubtitle: String?
    var createdAt: Date
}
```

`kind` is backed by a `ClipboardHistoryKind` enum:

```swift
enum ClipboardHistoryKind: String, CaseIterable, Sendable {
    case ocr
    case color
    case qrcode
    case screenshot
}
```

The raw string is persisted so SwiftData stores a stable primitive value.

### Field Semantics

- `text` stores OCR text, QR payload text, and the HEX value for color records.
- `colorHex` stores color records redundantly for clear rendering and
  validation without parsing arbitrary text.
- `fileName` stores only the PNG filename for screenshot records.
- `previewTitle` is the list row title:
  - OCR: first non-empty line, truncated for display by the view.
  - QR: first non-empty line, truncated for display by the view.
  - Color: the uppercase HEX value.
  - Screenshot: `截图`.
- `previewSubtitle` is short supporting context:
  - OCR: line count or character count.
  - QR: payload count when multiple codes were decoded.
  - Color: timestamp text is enough; this may be left nil if the row already
    shows the date.
  - Screenshot: image dimensions when available.
- `createdAt` drives sorting and pruning.

## Storage

The model is added to the existing `ModelContainer` in `AppDelegate`. It must
reuse the current fixed store path:

`~/Library/Application Support/dev.bybee.AnyDoor/AnyDoor.store`

Screenshot PNG files are stored in:

`~/Library/Application Support/dev.bybee.AnyDoor/ClipboardHistory/<uuid>.png`

SwiftData stores the screenshot metadata and the filename. It does not store
image bytes. This keeps the persistent store small and makes file cleanup
straightforward.

## Architecture

### `ClipboardHistoryStore`

Add an independent store:

```swift
@MainActor
@Observable
final class ClipboardHistoryStore {
    static let shared = ClipboardHistoryStore()

    func bootstrap(modelContainer: ModelContainer)
    func recordText(kind: ClipboardHistoryKind, text: String) async
    func recordColor(hex: String) async
    func recordScreenshotFromPasteboard() async
    func recentItems(kind: ClipboardHistoryKind) -> [ClipboardHistoryItem]
    func copyToPasteboard(_ item: ClipboardHistoryItem) async throws
    func pruneExpiredAndOverflow() async
    func clearAll() async
}
```

The store owns all history-specific behavior:

- SwiftData fetches and saves.
- Screenshot file writes and deletes.
- Pruning expired and overflow records.
- Orphan PNG cleanup.
- Pasteboard writes from stored history.

It does **not** own panel rows or hotkeys. `PanelStore` remains responsible for
built-in panel state, provider dispatch, and hotkey snapshots.

### `BuiltinItem.historyKind`

Add a derived property:

```swift
var historyKind: ClipboardHistoryKind? {
    switch self {
    case .ocr: return .ocr
    case .pickColor: return .color
    case .qrcode: return .qrcode
    case .screenshot: return .screenshot
    default: return nil
    }
}
```

This keeps `BuiltinItem.Kind` unchanged. These rows remain actions, not
submenus.

### `ClipboardHistoryPopoverView`

New SwiftUI view mounted inside `HoverPopover`:

```swift
struct ClipboardHistoryPopoverView: View {
    @Bindable var store: ClipboardHistoryStore
    let kind: ClipboardHistoryKind
    let onClose: () -> Void
}
```

Responsibilities:

- Fetch and render `store.recentItems(kind:)`.
- Track selected item.
- Update selection on hover and arrow keys.
- Handle `Space`, `Enter`, and `Esc`.
- Show previews.
- Call `store.copyToPasteboard` for click / `Enter`.
- Call `onClose` after successful copy.

Keyboard monitoring can follow the `PortManagerPopoverView.KeyboardMonitor`
pattern. The monitor should extract Sendable primitives from `NSEvent` before
using `MainActor.assumeIsolated`, matching the existing Swift 6 safety pattern.

## Data Flow

### Startup

1. `AppDelegate.init()` creates `ModelContainer` for:
   - `KeyBinding`
   - `BuiltinPreference`
   - `ClipboardHistoryItem`
2. `AppDelegate.applicationDidFinishLaunching` calls:
   - `ClipboardHistoryStore.shared.bootstrap(modelContainer:)`
   - `Task { await ClipboardHistoryStore.shared.pruneExpiredAndOverflow() }`

### OCR success

1. `OCRProvider.run()` captures a region and recognizes text.
2. It writes recognized text to `NSPasteboard.general`.
3. It calls `ClipboardHistoryStore.shared.recordText(kind: .ocr, text: text)`.
4. It shows the existing success toast.

History write failure is logged and does not alter the success toast.

### QR success

1. `QRCodeProvider.run()` captures a region and decodes QR payloads.
2. It writes newline-joined payloads to `NSPasteboard.general`.
3. It calls `recordText(kind: .qrcode, text: text)`.
4. It shows the existing success toast without payload content.

### Color success

1. `PickColorProvider.run()` receives a HEX value from `ColorSampler`.
2. It writes the HEX value to `NSPasteboard.general`.
3. It calls `recordColor(hex:)`.
4. It shows the existing color toast.

### Screenshot success

1. `ScreenshotProvider.run()` still calls:
   - `/usr/sbin/screencapture -i -c`
2. If the command succeeds, it calls `recordScreenshotFromPasteboard()`.
3. `recordScreenshotFromPasteboard()` reads the current pasteboard image data,
   normalizes it to PNG, writes it to the history directory, and creates the
   SwiftData metadata row.

`screencapture` cancellation remains a no-op. If the pasteboard does not contain
decodable image data after a successful command, history recording logs and
returns without user-visible failure.

### Hover history

1. `MenuBarView` renders each action row normally.
2. If the underlying `BuiltinItem` has a `historyKind`, the row also installs
   `ScreenFrameReader` and `onHover`.
3. On hover, `MenuBarView`:
   - sets an active popover target for that history kind,
   - calls `ClipboardHistoryStore.shared.pruneExpiredAndOverflow()`,
   - mounts `ClipboardHistoryPopoverView`,
   - sets `popover.needsKeyFocus = true`,
   - shows the popover anchored to that row.
4. Click on the action row still runs `PanelStore.run`.

## Pruning

Pruning runs:

- once after `ClipboardHistoryStore.bootstrap`,
- every time a history popover is opened,
- after each successful record insert.

Rules:

1. Delete rows with `createdAt < now - 7 days`.
2. For each `ClipboardHistoryKind`, keep newest 100 rows and delete older
   overflow.
3. Delete screenshot files referenced by deleted rows.
4. Delete orphan PNG files in the history directory that are not referenced by
   any remaining screenshot row.

If file deletion fails, log and continue. The next prune can retry.

## Error Handling

- Original action succeeds, history write fails: keep original success behavior,
  log history failure.
- Screenshot action succeeds, pasteboard image read fails: log and do not create
  a history item.
- Stored screenshot file is missing: render a missing-file state; click does not
  copy; preview shows failure.
- Copying a history item fails: show a toast `复制失败`.
- Prune fails partly: log and continue.
- QR payload is sensitive: do not show it in toast; do show it in the history
  UI because the user explicitly opened that UI.

## Testing

### Model and Store Tests

- Insert `ClipboardHistoryItem` rows and fetch newest-first per kind.
- `recordText(.ocr)` builds correct metadata and preserves full text.
- `recordText(.qrcode)` builds correct metadata and preserves full payload text.
- `recordColor` uppercases or preserves uppercase HEX and stores `colorHex`.
- 7-day prune deletes expired rows.
- 100-item cap deletes oldest overflow per kind.
- Screenshot record writes a PNG file and creates matching metadata.
- Deleting screenshot rows during prune deletes their PNG files.
- Orphan PNG cleanup removes unreferenced files.
- `copyToPasteboard` writes text-like records as `.string`.
- `copyToPasteboard` writes screenshot records back as image pasteboard data.
- Missing screenshot file copy throws a store error.
- `clearAll` deletes all rows and screenshot files.

### Built-in Integration Tests

- `BuiltinItem.ocr.historyKind == .ocr`.
- `BuiltinItem.pickColor.historyKind == .color`.
- `BuiltinItem.qrcode.historyKind == .qrcode`.
- `BuiltinItem.screenshot.historyKind == .screenshot`.
- Non-history built-ins return nil.
- The four history-capable rows remain `.action`.
- `PanelStore.rebuildHotkeySnapshots()` still includes action hotkeys for OCR,
  color, QR, and screenshot when assigned.

### UI Tests / View Tests

- `ClipboardHistoryPopoverView` empty state renders for no records.
- List state renders newest-first records.
- Hover updates selected item in the row view model.
- Arrow navigation clamps at the first and last item.
- `Space` toggles preview for selected item.
- `Enter` invokes copy and close.

If direct SwiftUI event-monitor testing is brittle, keep key behavior in a small
view model and test that instead. Do not turn the test suite into a ritual
bonfire for the sake of pretending AppKit keyboard events are fun.

## Scope Guard

This feature is deliberately a local generated-output history. It should not
grow pasteboard polling, global clipboard capture, search, sync, or custom
retention controls in this iteration. Those are separate product decisions.
