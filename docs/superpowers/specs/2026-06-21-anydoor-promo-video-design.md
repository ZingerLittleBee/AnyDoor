# AnyDoor Promo Video — Design

**Date:** 2026-06-21
**Status:** Approved (pending spec review)
**Tooling:** [Remotion](https://www.remotion.dev/) (video-as-React), rendered locally on macOS.

## 1. Goal

Produce a short, looping promo video that lives on the AnyDoor landing page
(`landing/`). The video sells the product's core differentiator — *a launcher
only searches; AnyDoor controls the whole Mac* — to keyboard-first developers,
using the same visual language and copy the landing page already ships.

The video is **pure motion graphics**: every frame is generated by Remotion
React components that re-create the landing page's UI mockups. No real screen
recordings or screenshots are required. Real recordings can be swapped in later
without reworking the storyboard.

## 2. Format (locked)

| Property | Value |
| --- | --- |
| Aspect / resolution | 16:9 · 1920×1080 |
| Frame rate | 30 fps |
| Duration | ~33 s (987 frames; final value tuned in Studio) |
| Audio | None — designed for `autoplay muted loop playsinline` |
| Loop | Seamless: the final frame returns to the opening state |
| Languages | **Chinese and English**, following the landing page language toggle |
| Tone | Refined, Apple-product-film pacing; dark throughout |

## 3. Narrative

One spine: **"The developer's system console."** Positioning line lifted from
`landing/src/lib/copy.ts` → `copy.why`:

> 启动器负责搜索，AnyDoor 控制整台 Mac。 / Launchers search. AnyDoor controls your Mac.

Six scenes, first and last designed to close the loop.

consistent with) `landing/src/lib/copy.ts` so the video and site never drift.

**Scene timing (30 fps), arranged with `TransitionSeries`:**

| Scene | Frames | Transition out |
| --- | --- | --- |
| 0 | 90 | fade 12 |
| 1 | 180 | fade 12 |
| 2 | 180 | fade 12 |
| 3 | 180 | fade 12 |
| 4 | 180 | fade/slide 15 |
| 5 | 240 | — |

Sum of sequences 1050 − transitions 63 = **987 frames ≈ 32.9 s**. Transitions
use the Apple deceleration curve `Easing.bezier(0.16, 1, 0.3, 1)`; a single
gentle overshoot (`Easing.bezier(0.34, 1.56, 0.64, 1)`) is reserved for one
emphasis beat (the app window spring in Scene 1).

## 5. Visual system

Ported verbatim from `landing/src/styles/global.css` into a Remotion
`theme.ts`:

- Background `#050507`; surface `rgba(28,28,32,0.85)`; hairlines `rgba(255,255,255,0.08)`.
- Accent `#0a84ff` / `#5e9bff`; macOS hues green `#30d158`, orange `#ff9f0a`, red `#ff453a`, purple `#bf5af2`, pink `#ff375f`.
- Accent gradient (headline): `linear-gradient(135deg, #5e9bff 0%, #bf5af2 60%, #ff375f 110%)`.
- Glass cards: the `.mbpanel` / `.popover` gradient + blur recipe.
- Fonts: **local Apple system fonts** — SF Pro Display/Text (UI), PingFang SC
  (Chinese), SF Mono (keys/code/ports). Referenced **by family name only** (no
  font files committed — avoids redistributing Apple fonts from a public repo);
  a `delayRender` + `document.fonts.load()` guard ensures glyphs are ready
  before the first rendered frame. Portable fallback (Inter / Noto Sans SC /
  JetBrains Mono via `@remotion/google-fonts`) is documented for CI/non-Mac
  renders but not the default.

**Remotion constraint honored throughout:** all motion is driven by
`useCurrentFrame()` + `interpolate()` + `Easing.bezier`. CSS transitions /
animations and Tailwind animation classes are forbidden (they do not render).
Static layout CSS from the landing page is reused; only the *animation* is
re-expressed through the frame system.

## 6. Technical architecture

### 6.1 Project layout

A self-contained Remotion workspace at the repo root, separate from the Astro
landing project so React/Remotion dependencies never mix into `landing/`.

```
video/
├── package.json            # remotion, react, @remotion/{transitions,fonts,media,google-fonts}, zod
├── remotion.config.ts
├── public/                 # door glyph (reused from landing/public/menubar-icon.png), any static art
├── src/
│   ├── Root.tsx            # <Composition id="AnyDoorPromo" 1920x1080 30fps> + Zod schema
│   ├── AnyDoorPromo.tsx    # TransitionSeries chaining Scene0..5; reads `lang` prop
│   ├── theme.ts            # color / gradient / font tokens (mirrors global.css)
│   ├── copy.ts             # bilingual strings (subset mirrored from landing copy.ts)
│   ├── fonts.ts            # loadFonts() with delayRender guard
│   ├── ui/                 # landing mockups re-built as React; motion = frame-driven
│   │   ├── MenuPanel.tsx   Keyboard.tsx        CommandPalette.tsx  PortManager.tsx
│   │   ├── DesktopStage.tsx ToggleCard.tsx     BrightnessOSD.tsx   CaptionChip.tsx
│   │   └── Backdrop.tsx     DoorGlyph.tsx
│   └── scenes/Scene0.tsx … Scene5.tsx
└── out/                    # render artifacts (gitignored)
```

### 6.2 Parameterization (bilingual)

Per Remotion's `parameters` rule, the composition takes a Zod-validated prop:

```ts
export const promoSchema = z.object({ lang: z.enum(['zh', 'en']) });
```

`Root.tsx` registers **two compositions that share one component**, so both are
previewable in Studio and renderable by id without juggling `--props`:

```tsx
<Composition id="AnyDoorPromo"   component={AnyDoorPromo} schema={promoSchema}
  defaultProps={{ lang: 'zh' }} width={1920} height={1080} fps={30} durationInFrames={987} />
<Composition id="AnyDoorPromoEn" component={AnyDoorPromo} schema={promoSchema}
  defaultProps={{ lang: 'en' }} width={1920} height={1080} fps={30} durationInFrames={987} />
```

Every caption reads `copy[key][lang]`.

### 6.3 Rendering & outputs

Render each language to web-ready files:

```bash
# from video/ — render each composition by id (props come from defaultProps)
npx remotion render AnyDoorPromo   out/promo-zh.mp4
npx remotion render AnyDoorPromoEn out/promo-en.mp4
# webm (VP9) fallback + poster still per language
npx remotion render AnyDoorPromo   out/promo-zh.webm --codec=vp9
npx remotion still  AnyDoorPromo   out/promo-zh.jpg  --frame=0
```

A small `video/scripts/render.sh` wraps the four-file matrix (zh/en × mp4/webm
+ posters) and copies results into `landing/public/`.

### 6.4 Landing-page integration

Outputs land in `landing/public/`:
`promo-zh.mp4`, `promo-zh.webm`, `promo-zh.jpg`, and the `en` trio.

New component `landing/src/components/Showcase.astro`, inserted in
`landing/src/pages/index.astro` **after `<Hero />`** (it *complements*, does not
replace, the interactive `HotkeyDemo`). It wraps a single `<video autoplay muted
loop playsinline preload="metadata">` in a macOS-window-style rounded card that
reuses the `.cap-screen` blue/purple gradient frame.

Language switching mirrors the rest of the site, which reacts to
`html[data-lang]`. Because a hidden `<video>` should not also be downloaded, the
component swaps the source instead of rendering both:

```ts
// Showcase.astro inline script
const root = document.documentElement;
const video = document.querySelector<HTMLVideoElement>('#promo-video');
const apply = (lang: 'zh' | 'en') => {
  const next = `/promo-${lang}.mp4`;
  if (video && !video.currentSrc.endsWith(next)) {
    video.poster = `/promo-${lang}.jpg`;
    video.src = next;          // (webm <source> handled the same way)
    video.load();
    video.play().catch(() => {}); // autoplay-muted is allowed; ignore rejection
  }
};
apply((root.getAttribute('data-lang') as 'zh' | 'en') || 'zh');
new MutationObserver(() => apply((root.getAttribute('data-lang') as 'zh' | 'en') || 'zh'))
  .observe(root, { attributes: true, attributeFilter: ['data-lang'] });
```

This needs **no change to `Nav.astro`** — the existing `setLang()` already
mutates `data-lang`, which the observer picks up. A `prefers-reduced-motion`
guard pauses autoplay and shows the poster.

## 8. Testing & verification

- **Per-scene visual check** in Remotion Studio (Studio is the live "visual
  companion" for this project).
- One-frame still renders at scene boundaries to catch layout/color drift.
- Loop check: compare frame 0 and the final frame — must be visually identical.
- Landing integration: toggle 中/EN and confirm the video source swaps and
  resumes; confirm autoplay-muted-loop works in Safari and Chrome; confirm the
  reduced-motion fallback.
- Font check: confirm CJK + Latin + mono glyphs render (no tofu) in the headless
  render, not just in Studio.

## 9. Decisions (resolved)

1. **Fonts** — local Apple system fonts by family name (no files committed);
   Google-Fonts fallback documented. ✅
2. **Project location** — standalone `video/` workspace. ✅
3. **Languages** — both zh + en, one parameterized composition, video source
   follows the landing language toggle. ✅
4. **Landing placement** — new `Showcase` section after `<Hero />`; keep the
   existing interactive `HotkeyDemo`. ✅

## 10. Out of scope (YAGNI)

- Voiceover / music (silent-loop by design; a separate "release cut" with audio
  could be produced later from the same project).
- Vertical (9:16) / square (1:1) social cuts — the composition is parameterized
  enough to add later, but not built now.
- Real screen recordings — the motion-graphics version ships first; recordings
  can replace individual scene mockups later.

## 11. Implementation phases (preview)

1. Scaffold `video/` (`create-video --blank`), add deps, theme + fonts + copy.
2. Build the shared `ui/` mockups (frame-driven ports of the landing mockups).
3. Build `scenes/0..5` and wire `AnyDoorPromo` via `TransitionSeries`.
4. Tune timing/easing in Studio; verify the seamless loop.
5. Render zh+en matrix; add `Showcase.astro`; wire the language observer.
6. Verify on the landing page (toggle, autoplay, reduced motion); commit.
